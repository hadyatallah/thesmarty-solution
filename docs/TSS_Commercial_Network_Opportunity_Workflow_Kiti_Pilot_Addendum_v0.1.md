# TSS Commercial Network Opportunity Workflow & Kiti Pilot Implementation Addendum
## Version 0.1 — Controlled DEV Pilot
**Date:** 6 October 2026
**Status:** Proposed implementation addendum. Not Master Playbook authority.
**Scope:** Controlled chat-managed pilot only. No Production deployment or live Kiti outreach.

## Purpose
This addendum turns the approved Commercial Network architecture into a controlled Kiti pilot without adding a second CRM, a seventh Commercial Network business entity, a public marketplace, or autonomous commercial authority.

The pilot covers derived operating phases, the Opportunity Workspace, readiness and authority views, evidence-backed Match evaluation, governed Opportunity Packs, proposal-first CRM Assistant behavior, commercial analytics, and positive/negative acceptance journeys.

## Architecture boundary
The six authoritative Commercial Network entities remain Company Role, Commercial Signal, Commercial Opportunity, Mandate, Match, and Partner Relationship. Company and Contact remain canonical operational identities.

The pilot preserves separate Opportunity status/development stage, separate Match qualification/engagement, suppression over fit, Mandate authority over action, D0-D6 disclosure, Unknown as Unknown, stale as not false, archive as not delete, and Qualified != Shortlisted != Outreach Approved.

## Chat-managed execution
For this phase, implementation must be executable through connected chat tools and repository/file connectors. No manual browser takeover is a prerequisite.

Chat-managed work may create isolated Git branches, pilot code, tests, evidence artifacts and Preview verification. Actions that the connected tools cannot safely perform are deferred rather than routed through paid third-party browsing tools.

Deferred in this phase: live Apps Script source replacement, Production deployment, live Kiti outreach, and external investor distribution.

## Operating phases
PREPARE: Opportunity remains under assessment/readiness.
LOAD: Accepted Opportunity is not yet fully ready for governed matching/execution.
LAUNCH: Targeting, qualification, shortlist and controlled outreach workflow.
CONVERT: Interest, introduction, active discussion, professional handoff, negotiation or outcome.

Operating phase is derived and never user-editable.

## Readiness
Readiness is a view, not an entity. States are Ready, Attention, Blocked and Not Applicable. It checks Opportunity readiness, target criteria, information package, Mandate status, authority and disclosure controls.

## Match methodology
Criteria remain Mandatory, Preferred and Informational.

Pilot criterion outcomes:
- Meets
- Does Not Meet
- Unknown
- Conflicting / Review Required
- Stale / Revalidation Required

Derived mandatory aggregate:
- PASS
- FAIL
- INCOMPLETE
- REVIEW REQUIRED

Derived working groups:
- Priority Review
- Standard Review
- Research First
- Blocked

No universal Match Score is permitted.

## Appetite rule
Capability never proves current appetite. Appetite requires relevant dated evidence such as current direct communication, a current Commercial Signal, or another explicit current requirement.

## Opportunity Packs
Pack generation follows governed source records → recipient context → disclosure projection → role template → drafting → validation → preview → human approval → governed artifact → audit.

Restricted Kiti information remains excluded unless specifically authorized. Default protected categories include landowner identity, architect identity, confidential studies, people behind TSS, and unapproved projections.

A Pack Manifest is supporting audit metadata, not a seventh Commercial Network entity.

## CRM Assistant
Required sequence: Observe → Resolve context → Interpret → Propose → Validate → Human approve → Execute → Audit.

The Assistant may propose engagement changes, next actions, follow-ups, questions, disclosure review and draft replies. It may not independently qualify, shortlist, approve outreach, raise disclosure authority, disclose restricted information, agree terms or send when approval is required.

## Analytics
Report Opportunity and Match progression, stage ageing, response quality, disclosure progression, pack/Assistant correction rates, governance blocks and conservative source attribution.

Do not implement AI close probability, weighted pipeline, universal Match score, arbitrary Opportunity health score, or email/record volume as success.

## Acceptance
Acceptance must prove protected CRM regression, workspace consistency, authority blocking, disclosure blocking, evidence/Unknown behavior, no role inheritance, no appetite inference, pack no-leak/no-invention behavior, Assistant proposal-only behavior, analytics reconciliation, idempotency/audit, mobile usability, a positive simulated journey and a negative governance-block journey.

Unauthorized disclosure, suppression bypass, unauthorized sending, canonical identity corruption or unsupported external factual claims are blocking defects.

## Current dependencies
Before live Commercial Network acceptance, reconcile the current DEV source state, establish a stable source baseline, complete the existing P0 acceptance prerequisite work, rerun persistent acceptance, and pass P0.5 protected CRM regression.

Before real Kiti developer qualification, complete the approved Company Data Center Preview write/read-back and final acceptance while preserving unresolved identities and gaps.
